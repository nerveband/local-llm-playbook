# Local LLM Working Rules

Keep context compact and fast on local inference:

1. Maintain a concise `notes.md` in the working directory with verified column names, row counts, decisions, created files, and the next pending step. Update `notes.md` after each verified milestone.
2. Inspect schemas before analysis and batch related read-only checks (column names, row counts, sample rows, summary counts) into 1 short Python or bash command instead of chaining separate `python3 -c` probes. Stream large CSVs line by line.
3. Use `read` (with `offset` and `limit`, or `pi-outline <file>` for long files) instead of `bash` `cat` or `sed`. Write separate small `.css`, `.html`, and `.js` template files (`<= 300` lines each) assembled by a tiny builder script rather than embedding HTML/CSS/JS inside one Python string. Use `write` for concise new `.py` scripts (`250` to `350` lines) and `edit` on existing files over `150` lines. Avoid bash heredocs (`<<EOF`).
4. Keep printed stdout summaries under 20 lines. Write full outputs (`.json`, `.csv`, `.html`) to disk instead of printing raw rows or large JSON blobs.
5. If a task names a skill, read it directly with `read` from `~/.config/skillshare/skills-shared/<name>/SKILL.md` without searching the filesystem.
6. Self-triggered phase boundary: when you finish a major phase or reach ~32K tokens (or see a local speed notice), update `notes.md` first, call `phase_handoff` only if another Pi phase remains (`auto_continue: false` to stop for review, or `auto_continue: true` only when requested), include exact verified column names and JSON keys in `summary`, set `next_thinking_level` (`low` for straightforward builds, `medium` for analysis or debugging), and stop calling tools immediately.
7. Adversarial self-check before finishing: assume newly written UI or script code has a subtle bug. Verify CSS grid/flex wrappers match the exact DOM nesting emitted by JS/HTML, verify tabs, filters, radios, and export act on the visible filtered list (not stale global IDs), null-guard persisted localStorage or imported IDs, verify scoring/tier distributions stay well calibrated, and run a real execution check.
8. Once you know the file paths or CSV columns, write your workspace deliverable (`.py` script or `notes.md`) directly instead of running repeated exploratory probes or `/tmp` scripts. Keep explicit prompt thresholds fixed instead of re-testing settled baselines.
9. For HTML/CSS/JS UI verification, run `pi-verify-ui /ABS/PATH/file.html` first (single-shot headless Chromium audit checking DOM counts, zero-size controls, console errors, and page errors), or pass `--eval-js` for compound interaction assertions. When using `agent-browser` directly, open with `AGENT_BROWSER_SESSION="ui-$$"`, batch assertions into 1 compound `eval` JSON IIFE, and close with `agent-browser close`. Skip fragile Node DOM stubs and jsdom.
10. macOS zsh omits GNU `timeout`; skip `timeout` prefixes in shell commands. Python and JavaScript/TypeScript files are automatically syntax-checked and linted (`ruff` / `oxlint`) after `write` and `edit`. If `edit` fails once on escaping in a file under 150 lines, rewrite cleanly with `write`.
11. For tabular deduplication or clustering, skip union-find on low-cardinality fields (status, category, year, institution). Guard `O(K^2)` pairwise loops when block size exceeds `50` and check cluster counts and runtime before scoring.
