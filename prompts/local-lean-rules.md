# Local LLM Working Rules

Keep context small and fast on local inference:

1. Maintain a concise `notes.md` file in the working directory with verified column names, row counts, decisions, created files, and the next pending step. Update `notes.md` after each verified milestone.
2. Inspect schemas before analysis and batch related read-only checks (column names, row counts, sample rows, summary counts) into 1 short Python or bash command instead of chaining separate `python3 -c` probes. Stream large CSVs line by line.
3. Use `read` (with `offset` and `limit`) instead of `bash` `cat` or `sed` to inspect files. Never embed large HTML/CSS/JS bundles inside one Python string: write separate small `.css`, `.html`, and `.js` template files (`<= 300` lines each) and assemble them with a tiny builder script so no single `write` exceeds ~5,000 tokens. Create concise new `.py` scripts (`250` to `350` lines when possible) with `write`, and patch existing files over 150 lines with targeted `edit` calls on specific sections rather than rewriting the whole file with `write`. Avoid bash heredocs (`<<EOF`).
4. Keep printed stdout summaries under 20 lines. Never dump raw CSV rows, full DataFrames, or large JSON blobs to stdout. Write full outputs (`.json`, `.csv`, `.html`) to disk.
5. If the user names a skill, read it directly with `read` from `~/.config/skillshare/skills-shared/<name>/SKILL.md` (and its `reference/*.md` files) without searching the filesystem.
6. Self-triggered phase boundary: when you finish a major phase or reach ~32K tokens (or see a local speed notice), update `notes.md` first, call `phase_handoff` only if another Pi phase remains (`auto_continue: false` to stop for user review, or `auto_continue: true` only when requested), include exact verified CSV column names and JSON keys in `summary`, set `next_thinking_level` (`low` for straightforward UI/CSV/script builds, `medium` for analysis or debugging), and stop calling tools immediately.
7. Adversarial self-check before finishing: assume your freshly written UI or script still has a subtle bug. Before declaring done, verify that CSS grid/flex wrappers match the exact DOM nesting emitted by JS/HTML, verify interactive controls (tabs, filters, radios, export) update state against the currently visible filtered list (not stale global IDs), null-guard persisted localStorage or imported IDs, and run a real verification check.
8. Action bias (no overthinking loops): once you know the CSV columns or file schema, immediately write your workspace deliverable (.py script or notes.md) instead of running another exploratory probe or /tmp script. Never re-test settled baselines or second-guess explicit prompt thresholds.
