# Local LLM Working Rules

Keep context compact and fast on local inference:

1. Maintain a concise `notes.md` in the working directory with verified column names, row counts, decisions, created files, and the next pending step. Update `notes.md` after each verified milestone.
2. Inspect schemas before analysis and batch related read-only checks (column names, row counts, sample rows, summary counts) into 1 short Python or bash command (`python3 -c` must stay under `800` chars) instead of chaining separate probes. Stream large CSVs line by line. Append `|| true` to `grep` checks expecting 0 matches.
3. Use `read` (with `offset` and `limit`, or `pi-outline <file>` for long files) instead of `bash` `cat` or `sed`. Write separate small `.css`, `.html`, and `.js` template files (`<= 250` lines each; split large UI JS into `state.js` + `render.js`) assembled by a tiny builder script rather than embedding HTML/CSS/JS inside one Python string or hitting single-turn output caps. Use `write` for concise new `.py` scripts (`250` to `350` lines) and follow the active `edit` tool schema for targeted edits, or use a short `python3 - <<'EOF'` patch script (`<= 4,000` chars) for tricky multi-hunk string edits (or the `code` / `python` tool if enabled). Still avoid `cat <<EOF > file` bash heredoc dumps.
4. Keep printed stdout summaries under 20 lines. Write full outputs (`.json`, `.csv`, `.html`) to disk instead of printing raw rows or large JSON blobs.
5. If a task names a skill, read it directly with `read` from `~/.config/skillshare/skills-shared/<name>/SKILL.md` without searching the filesystem.
6. Self-triggered phase boundary: when you finish a major phase or reach ~32K tokens (or see a local speed notice), update `notes.md` first, call `phase_handoff` only if another Pi phase remains (`auto_continue: false` to stop for review, or `auto_continue: true` only when requested), include exact verified column names and JSON keys in `summary`, set `next_thinking_level` (`low` for straightforward builds, `medium` for analysis or debugging), and stop calling tools immediately.
7. Adversarial self-check before finishing: assume newly written UI or script code has a subtle bug. Verify CSS grid/flex wrappers match the exact DOM nesting emitted by JS/HTML, verify tabs, filters, radios, checkboxes, and export act on the visible filtered list (not stale global IDs), null-guard persisted localStorage or imported IDs, verify round-trip UI state transitions (`A -> B -> A` plus page reload persistence, never stopping at `0` console errors alone), verify scoring/tier distributions stay well calibrated, and run a real execution check.
8. Once you know the file paths or CSV columns, write your workspace deliverable (`.py` script or `notes.md`) directly instead of creating multiple throwaway `_explore*`/`_probe*`/`_debug*` or `/tmp` scripts. Keep explicit prompt thresholds fixed instead of re-testing settled baselines.
9. For HTML/CSS/JS UI verification, use the `bash` tool with `pi-verify-ui` (already preinstalled on `PATH` at `~/.local/bin/pi-verify-ui`; never invoke it as a tool name and never run `find /`). Do NOT use `agent-browser`, `browser-use`, or custom `/tmp/*.mjs` / `node:vm` stubs: batch ALL functional DOM, interaction, filter, keyboard, export, and storage assertions into 1 compound `.js` check file (supporting multi-statement JS, trailing `;`, and `async`/`await` for debounced handlers) or inline IIFE passed via `pi-verify-ui --dom /ABS/PATH/file.html --eval-js check.js` (sub-second `happy-dom`), fix any failure, and finish with 1 real headless Chrome CDP run (`pi-verify-ui /ABS/PATH/file.html --eval-js check.js` without `--dom`) checking layout and zero console/page errors.
10. macOS zsh omits GNU `timeout`; skip `timeout` prefixes in shell commands. Python and JavaScript/TypeScript files are automatically syntax-checked and linted (`ruff` / `oxlint`) after `write` and `edit`. For `edit`, pass `edits` as a real JSON array (never a single-quoted string) and if an edit fails once on a small file (`<= 150` lines), rewrite cleanly with `write`.
11. For tabular deduplication or clustering, separate blocking keys from scoring signals: union-find ONLY on high-cardinality identifiers (email, phone, full street address, exact full name, username) and NEVER on columns marked `(distinct=...)` or dates, birth year, status, category, level, school, institution, or last4 (use those strictly as pairwise scoring bonuses inside already-blocked groups). Always union a block in O(K) (`for m in members[1:]: union(members[0], m)`), skip blocks with `len(members) > 50`, and guard every nested `i, j` pair loop with `len(members) <= 50`.
